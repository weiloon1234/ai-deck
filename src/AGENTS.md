# Vue frontend guidance

Inherits [root guidance](../AGENTS.md). This directory contains UI and its native command bridge.

- Keep screen-specific components in `features/<feature>/`; put only genuinely shared UI/state in `shared/`. Reuse feature components across screens when they display the same domain data.
- Follow Vue `<script setup lang="ts">` and the existing Composition API patterns. Use `useDeck()` for shared state, command invocation, refresh and error reporting. Do not add another global store or direct provider calls.
- `perform` handles ordinary operations; model analysis uses `modelOperation` and its own progress/cancellation state so deployment cleanup remains available.
- Import native types from generated `shared/contracts.ts`. Change their Rust definitions and regenerate instead of maintaining duplicate TypeScript shapes, policy defaults or provider metadata. `shared/providers.json` is also generated from Rust.
- Provider selection saves through `select_provider`; do not reuse a Runpod key for GPUtw. Clear draft keys and cached quotes/creation confirmations when selection changes. Show GPUtw as setup only until the native gate is resolved; never present a successful read check as provisioning or recovery validation.
- Keep cloud credentials, process launches, filesystem writes and authoritative validation in Rust. Disabled buttons help the user; they are not a security or spending boundary.
- Unconfirmed creation must explain that Reconcile searches rather than resends creation. Show the saved sanitized creation error independently of transient operation errors, keep Enable/Open CLI gated, and keep Resolve an absent creation visible beside Reconcile rather than hidden in deployment details. Reuse the existing typed-name confirmation and native absence checks.
- Treat model metadata/card/config text as untrusted. Use text interpolation, not `v-html`. Derive displayed facts from saved data; leave absent facts unknown. Do not infer parameter counts from names or inflate published context limits using RoPE factors.
- Preserve the distinction between published model limits and AI estimates. Use the shared model-details/hardware components in Models and deployment preparation. Provider quotes need their timestamp and storage exclusion.
- Model configuration expands inline from its saved card. Keep the draft separate from AI analysis and saved settings; failed/stale saves preserve it. Try experimentally saves through the native command and selects Deployment without provisioning. Use the saved model's provider for GPU options, label manual profiles untested, show the current read's price timestamp, and do not redirect the owner if a save completes after navigation. Explain missing local config without requiring reanalysis to try; protected models need the Runpod secret reference before paid creation. Configuration changes invalidate open paid confirmations.
- Use established styles in `shared/styles.css`, accessible labels and readable empty/busy/error states. Check the supported desktop window widths. Keep implementation details out of ordinary user flows unless they help a decision.
- Browser preview is intentionally unable to invoke native commands. Do not bypass that boundary for a visual test or ship test account/state fixtures in the production view.
- Provider/document links go through `deck.openExternal` and the native URL allowlist. When adding a link shape, update and test that native boundary as well as the rendered href; never allow arbitrary external URLs to make a link work.

For behavioral UI changes, read [test guidance](../tests/AGENTS.md) and reuse `tests/ui/component_fixture.cjs` and the existing compiler-based tests; do not install another test framework. Run `npm run test:ui` and `npm run build`. Cross-layer changes also follow the root validation workflow.
